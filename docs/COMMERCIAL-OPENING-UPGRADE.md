# Riftline — 开场体验升级

2026-10-26 · Unity 6000.6.7f1 · macOS Editor

本轮已经实现并验证“安保追逐 → 回收档案 → 抵达撤离点 → 下一契约”的开场流程。首页保持一键开跑；首个契约仍为 60 秒。新增工业航道、追兵和局部动作反馈，让任务、危险和完成目标在场景中可见。

## 玩家现在会看到什么

| 环节 | 已实现的变化 |
| --- | --- |
| 首页 | 当前任务与追兵提示；“立即开跑”直接进入推荐契约。 |
| 开跑 | 结构框架、护栏与灯带构成工业船坞；生成的安保无人机出现在航道外。 |
| 连收与相位 | 实际事件驱动局部能量响应、无人机反应和音乐强度；首次五连收在本次录像约 6.12 秒发生。 |
| 跳跃落地 | 真正落地时出现短暂地面光环，播放生成音效的短撞击片段。 |
| 受伤 | 沿用三格生命规则；生命减少后，无人机的距离、颜色和强度反映更高威胁。 |
| 档案 | 本局真正拾取档案后，HUD 切换为“前往撤离点”。录像中发生在约 37.50 秒。 |
| 最后 15 秒 | 撤离门出现在实际终点。 |
| 通关 | 确认撤离和本局档案回收，显示下一契约名称；下一契约成为主要按钮和默认 Enter 操作。 |
| 失败 | 保留准确的失败原因与建议；提示重试恢复满生命，并保留已获得进度。 |

无人机不增加隐藏的失败条件。装饰结构没有碰撞体，转弯处会跳过跨越路口的直线护栏。新反馈只作用于场景与跑者附近；导航逻辑继续保留设备对头部局部姿态的控制。

默认低闪光仍然开启：落地光环更窄、更淡，追兵灯与连收闪光受到限制；“减少粒子”关闭新增局部线条。录像为展示完整反馈，使用 `ReducedFlash=false / ReducedParticles=false`；默认设置另有暂停状态下的实测。

## 验证结果

**最终录像运行通过。** 使用全新隔离存档，`Time.timeScale=1`，通过生产 InputSystem 注入实际键盘与鼠标事件；没有自动驾驶、快进或直接改写生命/关卡结果。

结果为 **60.00 秒通关、1 次真实碰撞、剩余 2/3 生命、18,604 分、43 枚晶片、档案成功回收**。录制涵盖连收、跳跃、滑铲、左右转弯、相位、撤离、中英文结算与鼠标点击下一契约；下一关恢复三格生命。

## 媒体与环境恢复

录像来自 ScreenCaptureKit 捕获的真实 Unity 窗口和应用音频。原始窗口为 1728×986，删除开头 12 秒准备画面，裁去上方 109 和下方 23 像素，导出 **1600×790 / 30fps / 71 秒**。未改变播放速度，也未配入额外声音。

完整解码 **2,130 帧**；一条音轨解码 6,815,840 个 PCM 样本，其中 6,798,403 个非静音。首页、受伤、动作、相位、撤离和结算帧已检查。

最终场景已保存至 `Assets/Riftline/Scenes/Riftline.unity`，Editor 回到 Edit Mode。Stats 恢复开启，Enter Play Mode Options 恢复关闭/None，临时设备和验收存档钩子已清除；自有新增网格/材质在退出时释放。录制前后普通存档 SHA-256 清单一致。最终控制台计数为 **0 errors / 15 warnings**，警告没有被清空或伪装为零。

早期驱动曾因 Editor 音频输出停滞、Retry 尚未就绪和落地采样过早而停止。原始失败报告保留在证据中；最终判定来自独立的通过运行，详见 [驱动诊断说明](commercial-opening/harness-diagnostics/README.md)。
